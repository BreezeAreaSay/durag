# DURAG — серверная многопользовательская карточная игра (Telegram Mini App / PWA)

Динамичная модификация «Дурака»: подкидывание без очереди, скрытый козырь, два Джокера, Супер-карта и «пеньки».
Сервер — единственный источник правды (authoritative server), клиент отправляет намерения (intents) и рендерит состояние.
Визуальный стиль — Indie Punk & Glitch (v10): тёмная потёртая бумага с грубым зерном, кислотно-жёлтые «скотч»-плашки,
ровные карты, токсичная маджента вместо красных мастей, распад карт под Супер-картой. Шейдерных фильтров нет совсем:
на iPhone (WebKit) они давали чёрную карту вместо Супер-карты, поэтому вся графика — чистая векторная геометрия.
LLM-боты (раздел 2 ТЗ v10): соперники, которых сажают за стол кнопкой в лобби; играют по встроенным правилам, а с ключом
OpenRouter/DeepSeek/Qwen — спрашивают модель (ход + короткая реплика), реагируют на эмодзи и раз за игру ломают четвёртую стену.

> English: authoritative multiplayer Durak variant. Go + Redis + WebSockets backend, React/Vite/TypeScript + PixiJS client,
> Telegram Mini App auth (HMAC-SHA256 of `initData`). See sections below for the protocol and deployment.

## Быстрый старт

### Вариант 1 — docker-compose (redis + golang + node)

```bash
cp .env.example .env          # впишите TELEGRAM_BOT_TOKEN; для локальных тестов ALLOW_DEV_AUTH=true
docker compose up
```

* Фронтенд: <http://localhost:5173> (Vite dev-сервер проксирует `/ws` и `/api` на бэкенд)
* Бэкенд: <http://localhost:8080/healthz>

### Вариант 2 — локально без Docker

```bash
# бэкенд (без Redis: in-memory хранилище)
cd backend
ALLOW_DEV_AUTH=true REDIS_ADDR= PORT=8080 go run ./cmd/server

# фронтенд
cd frontend
npm install
npm run dev
```

Откройте <http://localhost:5173> в двух вкладках/браузерах (в dev-режиме имя вводится вручную, Telegram не нужен),
создайте стол в одной, введите код во второй, нажмите «Готов» в обеих.

## Переменные окружения

Файл `.env` (см. `.env.example`) читается бэкендом и docker-compose.

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота из @BotFather. Нужен для проверки подписи `initData`. |
| `ALLOW_DEV_AUTH` | `true` — разрешить вход без Telegram (`dev_user` в `JOIN_ROOM`). **Только для разработки.** |
| `PORT` | Порт бэкенда (по умолчанию `8080`). |
| `REDIS_ADDR` | `host:port` Redis. Пусто — in-memory хранилище (один инстанс, состояние теряется при рестарте). |
| `REDIS_PASSWORD`, `REDIS_DB` | Доступ к Redis. |
| `ALLOWED_ORIGINS` | Список Origin через запятую для WebSocket (`*` — любой). В проде ставится `https://$DOMAIN`. |
| `ROOM_TTL` | Время жизни неактивной комнаты в Redis (`24h`). |
| `TG_INITDATA_MAX_AGE` | Максимальный возраст `initData` (защита от replay), `0` — не проверять. |
| `BOUT_RESOLVE_DELAY` | Сколько законченный кон остаётся на столе перед уборкой карт (`3500ms`). `0` — убирать мгновенно. |
| `STUMP_AUTO_DELAY` | Сколько после кона игрок может сам взять пенёк (`TAKE_STUMP`), прежде чем сервер возьмёт его за игрока (`4s`). `0` — брать мгновенно. |
| `TURN_TIMEOUT` | Таймер хода (`45s`): по истечении сервер делает ход по умолчанию (атакующий ходит младшей картой, защищающийся берёт, подкидывающие говорят «бито»). `0` — без таймера. |
| `MAX_ATTACKS` | Потолок атакующих карт за кон. По умолчанию `0`: ограничивает только рука защищающегося; `6` — классика. |
| `ADMIN_IDS` | Telegram user id админов через запятую (dev-вход: `dev:<id>`). Им в лобби показывается чип «АДМИН-ПАНЕЛЬ»: аптайм, счётчики, состояние LLM, столы и игроки, XP, ошибки правил, последние строки лога. Админам открыты все реакции с эффектами независимо от XP. |
| `BOTS` | `true` — в лобби доступна кнопка «+ добавить бота». |
| `LLM_API_KEY` | Ключ OpenRouter (`sk-or-…`) или другого OpenAI-совместимого API. Пусто — боты играют по встроенным правилам. |
| `LLM_BASE_URL`, `LLM_MODEL`, `LLM_TIMEOUT` | Провайдер и модели для ботов: по умолчанию `https://openrouter.ai/api/v1`, `openrouter/free` (бесплатный роутер OpenRouter), `10s`. `LLM_MODEL` — список через запятую, модели пробуются по очереди. |
| `LLM_FREE_ONLY` | `true` (по умолчанию) — платные ID из `LLM_MODEL` отбрасываются с предупреждением в логе; ключ не может потратить деньги случайно. `false` — разрешить платный fallback. |
| `LLM_MOVES` | `false` (по умолчанию): ходы делают правила, модель только говорит после хода. `true` — модель выбирает ход сама (старый режим). |
| `LLM_DISCOVER` | `true` (по умолчанию) — при старте и раз в час сервер читает `GET /models` провайдера и добавляет в список бесплатные модели (DeepSeek, Qwen, Llama… в порядке предпочтения), чтобы переименованный `:free` не оставил ботов без модели. |
| `BOT_DELAY_MIN`, `BOT_DELAY_MAX` | Человеческая пауза перед ходом бота (`900ms`–`2200ms`). |
| `FLY_CHANCE`, `FLY_DELAY_MIN`, `FLY_DELAY_MAX` | Муха за +1 XP: доля партий с мухой (`0.35`) и когда она вылетает после старта (`20s`–`90s`). |
| `DOMAIN`, `CERTBOT_EMAIL` | Только прод: домен и почта для Let's Encrypt. |
| `VITE_BOT_USERNAME`, `VITE_APP_SHORTNAME` | Фронтенд: для генерации deep-link `https://t.me/<bot>/<app>?startapp=<КОД>`. |
| `VITE_WS_URL` | Фронтенд: явный адрес WebSocket (по умолчанию `ws(s)://<host>/ws`). |

## Правила и принятые трактовки

Реализованы требования раздела 1 ТЗ. Там, где ТЗ допускает несколько прочтений, выбрано и зафиксировано тестами следующее.

**Колода — 55 карт.** 52 базовые (2…A четырёх мастей), Красный Джокер `RJ`, Чёрный Джокер `BJ`, Супер-карта `SC`.
ID карт: `H_10`, `S_14` (туз пик), `RJ`, `BJ`, `SC`. Ранги: 2…14, Джокер — 15, Супер — 16.

**Раздача.** Каждому по 6 карт в руку и 2 скрытые карты в «пенёк». Козырь выбирается случайно и кладётся под низ колоды
рубашкой вверх; его масть никому не известна и **не действует**, пока не кончится основная колода.
После каждого кона игроки добирают из колоды до 6 карт: сначала атакующий, затем остальные по кругу, защищающийся — последним.

* *Трактовка:* козырь выбирается среди 52 базовых карт, чтобы козырная масть существовала всегда.
* **Вскрытие козыря.** Козырная карта остаётся рубашкой вверх, пока её **не заберёт конкретный игрок** при доборе (она
  добирается последней). В этот момент карта вылетает в центр стола лицом ко всем, затем уходит в руку взявшему;
  с этого момента масть известна (`trump_card`, `trump_drawn_by`) и начинает действовать. Пока основная колода пуста,
  но козырь ещё не взят, козырей в игре нет.

**Право первого хода:** 2♠ → 3♠ → 4♠ → 5♠ → 6♠ → 2♣ (у кого есть карта раньше по списку). Если ни у кого нет ни одной из них — случайный игрок.

**Ход и отбой.**

* Первую карту кона кладёт атакующий (любую). Дальше **любой игрок, кроме защищающегося**, может подкидывать карты,
  достоинство которых уже есть на столе (среди атакующих или отбивающих карт). Лимита на число карт нет.
* **Лимит подкидывания — рука защищающегося.** Пока защищающийся отбивается, на столе не может лежать больше
  неотбитых карт, чем карт у него в руке: подкинуть можно, только если у него есть карта и на эту атаку
  (`TOO_MANY_ATTACKS`; при пустой руке — `DEFENDER_HAS_NO_CARDS`). Как только защищающийся отбил последнюю карту
  последней своей картой, кон закрывается сразу — «успеть подкинуть» в этот момент нельзя. **После «беру» лимита по
  руке нет**: докидывать можно любое число карт подходящих достоинств. Потолка на число атак за кон по умолчанию нет
  (`MAX_ATTACKS=0`); `MAX_ATTACKS=6` включает классический потолок, включая переводы.
* Защищающийся бьёт карту: той же мастью старше, либо (после вскрытия козыря) козырем; или **переводит**, или **берёт**.
* Взятие: защищающийся объявляет «беру», остальные могут докинуть карты того же достоинства, после чего он забирает **весь стол**.
  Следующий ход — игрока после взявшего (взявший пропускает атаку).
* «Бито»: когда все карты отбиты, подкидывающие говорят «бито» (`RESOLVE_BOUT`, старое имя `PASS` тоже принимается). Игрок, у которого нет ни одной карты, которую можно
  подкинуть, считается сказавшим «бито» автоматически (константа `AutoPassWhenNoLegalThrowIn` в `validator.go`).
  Успешно отбившийся атакует следующим.
* **Пауза после кона.** Законченный кон (бито или взятие) остаётся на столе `BOUT_RESOLVE_DELAY` (по умолчанию 3,5 с)
  в фазе `phase: "resolving"` со штампом «БИТО» / «X БЕРЁТ»: видно, кто что чем отбил. Ходы в это время отклоняются
  (`RESOLVING`), затем сервер сам убирает карты, раздаёт добор и назначает роли.

**Перевод.** Защищающийся кладёт карту того же достоинства, что и атакующие карты (пока ни одна не отбита), и защита
переходит к следующему игроку. Разрешён с самого первого хода. Переводивший становится ведущим атаки.
Джокер переводится **только Джокером другого цвета** (на обычную карту Джокер не ложится: `TRANSFER_RANK`).
Супер-картой переводить **нельзя**.
Классическое ограничение: у следующего игрока должно быть не меньше карт, чем атакующих карт окажется на столе после
перевода (`TRANSFER_TOO_FEW_CARDS`), поэтому перевести на игрока без карт невозможно.

**Спецкарты.**

* Супер-карта бьёт абсолютно любую карту и не бьётся ничем. Ею можно и ходить — тогда защищающемуся остаётся только взять.
* Красный Джокер бьёт любую красную карту (♥ ♦, включая красный козырь), Чёрный — любую чёрную, и каждый Джокер бьёт
  Джокера другого цвета. Джокеры не имеют козырной масти: козырь Джокера не бьёт. Побить Джокера можно Супер-картой
  или другим Джокером.

**Пеньки и выход (v10).** Пенёк берётся **строго отдельным шагом после завершения кона**, а не посреди него. Когда кон
закончен (бито или взятие), сервер раздаёт добор; если колода (вместе с козырем) исчерпана и у игрока опустела рука, но
есть пенёк, игрок попадает в `stump_pending`, а стол переходит в шаг «пеньки»: обычные ходы отклоняются (`STUMP_PENDING`),
игрок жмёт «ВЗЯТЬ ПЕНЁК» (`TAKE_STUMP`, карты вылетают из его стопки пенька в руку), либо по истечении `STUMP_AUTO_DELAY`
(по умолчанию 4 с) сервер берёт пенёк за него. Пенёк можно взять только в этом шаге (`NO_STUMP` — если его нет или
брать ещё рано). Игрок, у которого в этот момент нет ни карт в руке, ни пенька, выходит из игры победителем
(лог `out`). Последний оставшийся с картами — Дурак; если двое вышли одновременно — ничья.

**Таймер хода.** У каждого, кто сейчас должен действовать (`turn_actors`), идёт таймер `TURN_TIMEOUT` (по умолчанию 45 с),
нарисованный штрихованным кольцом вокруг аватара. По истечении сервер делает ход по умолчанию (лог `timeout`):
атакующий заходит младшей картой, защищающийся берёт, подкидывающие считаются сказавшими «бито».

**Пенёк переходит в следующую партию.** Если партия закончилась, а игрок так и не дошёл до своего пенька, в следующей
партии эти скрытые карты остаются у него (в колоду не возвращаются) и к пеньку сдаётся ещё одна карта сверху
(2 → 3 → 4…; лог `stump_grow`). Если карт на всех не хватает (большой стол после нескольких партий), пеньки сбрасываются до 2.

**Реакции.** Тап по аватарке открывает панель эмодзи (две страницы и ряд быстрых фраз); реакция (`SEND_EMOJI`, старое имя `REACT`) рассылается всем в комнате (`REACTION`) и на
3 секунды всплывает у аватара отправителя. Белый список эмодзи и лимит одной реакции в 1,2 с заданы на сервере.
Реплики (текст в `REACTION`) не висят у аватара, а идут в ленту под соперниками (`TalkFeed`): во всю ширину, без
обрезки, две последние строки, по 6 с каждая — реплики двух ботов больше не рисуются друг на друге.

**Места за столом.** Соперники показаны по кругу от зрителя (сосед слева всегда слева), до трёх в одну строку.
От девяти карт рука раскладывается в два ряда (`handSlots`: верхний ряд из первой половины карт выглядывает над
нижним и чуть уже его), полоса действий поднимается вместе с рукой.

**Лобби.** 2–4 игрока. Игра стартует автоматически, когда все нажали «Готов». Выход во время игры = сдача (карты в отбой,
если остался один игрок — вышедший объявляется проигравшим). Разрыв соединения во время игры сохраняет место за игроком.

## Прогресс игрока: победы, скины, рамки

**Победы.** Сервер считает победы по Telegram id (dev-id в dev-режиме): +1 получает **первый вышедший** из законченной
партии (`finished_order[0]`), боты и ничья не считаются. Счётчик хранится в Redis (`durag:wins:<id>`, без TTL) или в
памяти, начисляется ровно один раз под блокировкой комнаты (`win_awarded` в состоянии), и приходит всем в `Player.wins`.
Клиент кэширует свои победы в `localStorage`, чтобы раздел «Скины» работал до входа в комнату.

**Рамки аватара** (`frontend/src/util/progress.ts`): уровень `k = min(20, floor(wins / 5))`, цвет `hsl(220 + 14k, 90%, 55%)`,
с 50 побед (`k ≥ 10`) рамка крутится и светится, скорость `6 − 0.4(k − 10)` с на оборот и свечение `2(k − 10)` px.
Всё на CSS-переменных, без JS в кадре.

**Скины.** Таблица рубашек с порогом побед: «Классика» (0), «Чёрная в крапинку» (10, гексагональная решётка точек),
«Клетка» (20), «Звёзды» (30), «Волны» (40), «Кислота» (50, полосы токсичного и кислотного). Все рисуются примитивами
в `CardView` (`buildXBack`) и дублируются CSS-превью на экране скинов. Выбор хранится в `localStorage`, рубашку видит
только сам игрок (колода, отбой, пенёк).

**Вторая страница реакций и быстрые фразы.** Реакции первой страницы открывает опыт (XP), второй — победы: 🤝 (5),
🧨 (10), 🐓 (15), 👑 (20), 🥂 (30), каждая со своим эффектом и звуком (`PremiumEmoji.Wins`, проверка на сервере:
`xp ≥ XP || wins ≥ Wins || admin`). Быстрые фразы (`SAY {text}`, список `AllowedPhrases`: «easy», «бери давай»,
«ну и ход», «не спи», «это всё?», «ха», «заберёшь», «ой») открываются с 10 побед (`LOCKED_PHRASE`) и приходят всем
как `REACTION` с текстом — в ту же ленту, что и реплики ботов.

**Муха.** В `FLY_CHANCE` партий (по умолчанию 35 %) через `FLY_DELAY_MIN…MAX` после старта сервер выпускает над столом
муху (`FLY {id, seed}`): 🪰 семь секунд зигзагом летит по столу и жужжит. Первый, кто по ней хлопнул (`CATCH_FLY {id}`),
получает +1 XP (`store.AddXP`), остальным приходит `FLY {caught_by, xp}`. Решает сервер, так что очко нельзя получить
из консоли браузера.

**Физика карт.** Карта летит к слоту `160 + 9·√d` мс (d — расстояние) и садится по затухающему косинусу
`land(t) = 1 − (1 − t)²·cos(1.5πt)`: один мягкий перелёт на 11% и возврат. Эмодзи вылетают из аватара в центр стола
по дуге (линейный X, ease-out Y) и растворяются параллельно. Каждая карта ложится со своим наклоном и сдвигом
(`jitterSlot`: хеш id карты, одна из десяти — небрежно, до 0,35 рад), одинаково у всех игроков.

**Живой стол.** 👊 — удар кулаком: у всех в комнате карты подпрыгивают волной от центра (`h = H·e^(−d/R)`, задержка
`d/v`), экран трясётся, телефон вибрирует; двойной тап по пустому столу шлёт тот же 👊. 🚬 — сигарета и дым у
аватара вместо полёта (боты закуривают, когда берут стол). Джокер в атаке «подмигивает» оборотом вокруг оси
(`scale.x = cos πt`), Джокер, побивший карту, «смеётся» тремя подскоками `A·|sin ωt|·e^(−λt)` и выпускает 😂.

**Звук** (`util/audio.ts`): синтез на лету через Web Audio, без файлов, по умолчанию выключен, кнопка 🔊 в шапке стола.
Гул помещения — коричневый шум `b[n] = (b[n−1] + 0.02·w)/1.02` через полосовой фильтр с LFO; шлепок карты — всплеск
шума с огибающей `e^(−t/τ)`; удар — синус 70→35 Гц; «бито» и «берёт» — свои короткие сигналы.

**Темы.** Светлая бумага по умолчанию, тёмная (глубокий почти чёрный `#07070b`, не серый) — переключатель ☾/☀ в лобби и
в шапке стола, выбор в `localStorage`. CSS-токены переключаются атрибутом `data-theme`, Pixi-стол пересобирается
с цветами темы.

## LLM-боты (ТЗ v10 §2)

В лобби кнопка «+ ДОБАВИТЬ БОТА» сажает за стол соперника (`ADD_BOT`), «✕» убирает (`REMOVE_BOT`). Бот всегда «готов»,
занимает обычное место (хотя бы одно место остаётся людям), в лобби помечен бейджем «бот». Когда последний человек
выходит, стол удаляется.

* **Три персонажа** (`bot.Characters`, `people.go`): Вася 🥴 — непутёвый сосед по коммуналке, Бабуля 👵 — соседка из
  той же квартиры со своими порядками, Крест 🕶 — спокойный авторитет. Первый свободный садится за стол; аватар — эмодзи
  (`Player.avatar`). У каждого свой пул реплик на события стола (заход, взятие, перевод, одинокий защитник, пресс,
  охота, ответ на эмодзи, повышение) и своя роль для модели (`Persona` в `TalkPrompt`): говорить про игру, обращаться
  по имени, коротко. Реплик стало меньше: `SpeakEvery = 6` (реплика раз в ~6 заметных событий по золотому сечению),
  в комнате не чаще одной реплики любого бота за 9 с (`botRoom.lineCooldown`), ответ на эмодзи с шансом 0,2 и только
  когда кулдаун свободен.
* **Сила.** При живой колоде бот не заходит тузами и королями, пока в руке есть обычная карта до десятки, пара даёт
  бонус только мелочи, бьющему защитнику дорогие карты не подкидываются; берущему сбрасывается пачка мусора. Уровни:
  лёгкий иногда берёт и говорит «бито» зря (`Slip`), обычный играет по плану, сложный считает карты (`Memory`: лог стола
  по `seq`, точный до карты — тест `TestMemoryTracksTheDiscardExactly`) и при пустой колоде перебирает эндшпиль
  (`bot/endgame.go`): неизвестные карты раздаются случайно несколько раз (детерминизация), каждый ход проверяется
  плейаутами эвристики или альфа-бетой на клоне движка, бюджет 150 мс. В эксперименте (`STRENGTH=1 go test -run
  TestEndgameSearchExperiment ./internal/bot/`) перебор снижает поражения сложного бота против обычного с ~49 % до ~32 %.

* **Ходит сервер.** После каждого изменения состояния хаб смотрит, кто должен действовать (`Actors()` + шаг «пеньки»), и
  ставит таймер на `BOT_DELAY_MIN…MAX`. Таймер несёт `version` состояния: бот ходит ровно один раз на одно состояние и
  никогда — на устаревшее (`store.Update` отклоняет ход, если версия ушла). Ход выбирается только из `LegalMoves()` —
  списка, который строится прямо из валидаторов, поэтому бот не может сделать то, что отклонил бы сервер.
* **Два мозга, одна роль у каждого.** `bot.Heuristic` — правила, которые делают ходы: заходят мелочью и парами (вторая
  карта пары подкидывается сразу), берущему сбрасывают мусор пачкой, бьющему не подкидывают то, что он покроет даром,
  переводят раньше, чем тратят козырь, козыри и спецкарты берегут, пока жива колода, Супер-карту держат на последний
  заход, а при пустой колоде считают шансы соперника побить каждую карту. `bot.LLM` — чат-модель через
  OpenAI-совместимый `/chat/completions` (OpenRouter по умолчанию). По умолчанию модель **не ходит, а говорит**
  (`LLM_MOVES=false`): после хода правил ей асинхронно шлют стол, последнее событие и досье, она отвечает одной репликой
  `{"say": "…", "emoji": "…"}`, которая приходит пузырём, не задерживая игру. `LLM_MOVES=true` возвращает старый режим:
  модель получает пронумерованные легальные ходы и совет правил и выбирает ход сама (любая ошибка или тайм-аут →
  ход правил).
* **Бесплатно и лимиты.** `LLM_MODEL` — список через запятую, модели пробуются по очереди: неизвестная или упавшая
  (404, 5xx) или ответившая не по форме → следующая; провайдер без JSON-режима (400 на `response_format`) → повтор без
  него. «Думающие» модели (DeepSeek R1, QwQ, Qwen3 с рассуждениями) получают `reasoning: {"enabled": false}` и
  подсказку `/no_think`, бюджет ответа — 700 токенов; если модель всё равно думает и `content` пуст, JSON ищется в её
  рассуждениях (`reasoning`), а сервер, не знающий параметр `reasoning` (400), получает повтор без него. Дефолт
  `openrouter/free` — роутер OpenRouter, который сам берёт любую доступную сейчас бесплатную модель (конкретные
  `…:free` ротируются без предупреждения); после чтения каталога (`LLM_DISCOVER`) роутер пробуется последним, а
  модели, которые всегда рассуждают, — после обычных; внутри семейства первыми идут быстрые (меньше активных
  параметров). Модель, у которой перегружен провайдер (429 «upstream»), которой нет (404) или которая не уложилась в
  таймаут, отдыхает 2–10 минут, остальные пробуются; пауза всего мозга — только на лимиты аккаунта (429 без «upstream»,
  402). Неудачная проба при старте повторяется каждые 2 минуты до первого успеха (до 10 раз); отдыхающие модели видны
  в админ-панели. Бесплатный уровень OpenRouter: 20 запросов/мин и 50/день, пока
  на аккаунте ни разу не покупали кредиты на $10, после — 1000/день. После `429` боты 5 минут, после `402` — час играют
  по правилам без обращений к сети, затем пробуют снова (после дневного лимита — до полуночи UTC, после минутного —
  минуту). Стабильное платное: `deepseek/deepseek-chat` (дёшево) — но при `LLM_FREE_ONLY=true` (дефолт) платные ID
  отбрасываются. При старте сервер делает один пробный запрос и пишет в лог `bots: LLM probe ok model=…` (какая
  модель реально ответила) или `LLM probe failed` с причиной.
* **Эмодзи меняют характер.** Реакции людей (`SEND_EMOJI`) кормят настроение ботов комнаты на 90 с: провокации
  (😡 🔥 💀 👎) — агрессивная игра (переводит всегда, подкидывает больше, заходит парными достоинствами), насмешки
  (😂 🤡) — осторожная (бережёт старшие козыри, берёт раньше), остальное — ровная. Бот иногда отвечает своим эмодзи.
* **Реплики.** Короткий текст бота приходит как `REACTION` с полем `text` и показывается в ленте под соперниками
  (`TalkFeed`, две последние строки). Бот говорит редко (`SpeakEvery = 6`, золотое сечение в `bot/banter.go`
  раскладывает реплики ровно и без ритма, плюс комнатный кулдаун 9 с) и только по заметному поводу: взял три карты и
  больше, перевёл, остался с одной картой; смена плана на «пресс» или «охоту» изредка объявляется. Без модели — шаблонные
  подколы; с моделью — её фраза по тому же поводу.
* **Уровни.** Рядом с «+ ДОБАВИТЬ БОТА» чип уровня (лёгкий / обычный / сложный, `ADD_BOT {"level"}`, поле
  `bot_level` у места). Лёгкий играет небрежно: в 18 % решений берёт стол, который мог покрыть, или говорит «бито» с
  картой на руках, и не считает карты. Обычный играет по плану без подсчёта, изредка путает карту. Сложный никогда не
  ошибается и считает: память стола даёт шанс соперника побить каждую карту, по нему выбираются заходы и подкидывание
  в эндшпиле. В тесте `TestLevelsDiffer` сложный выигрывает у лёгкого около 70 % раздач, лёгкий у случайного игрока —
  около 85 %.
* **Планы.** Перед каждым ходом бот читает ситуацию (`bot.ChoosePlan`): «экономия», пока колода жива (мелочь в заход,
  козыри на защиту); «пресс», когда защитник тонет (7+ карт) или берёт; «сброс», когда своя рука разбухла (9+);
  «счёт» при пустой колоде; «охота», когда у кого-то 1–2 карты. Темп: между двумя картами одного бота в одном коне
  пауза 160–380 мс (вторая карта пары, следующая карта пачки берущему), между ходами — обычные `BOT_DELAY_MIN…MAX`.
* **Память стола** (`bot.Memory`, общая на комнату). Бот не видит чужих рук, но смотрит на стол: всё, что ушло в
  бито, вышло навсегда; всё, что игрок взял, лежит у него на руке, пока не появится на столе; а карты, которые бот
  взял, помнят, кто их подкинул. Из памяти считается шанс, что защитник побьёт карту: его неизвестные карты —
  случайная выборка размера h из U карт, которые бот не может разместить, B из них бьют; вероятность, что ни одной
  не досталось, — гипергеометрический хвост `Π_{i<h} (U−B−i)/(U−i)`; известная бьющая карта даёт 1 сразу. На
  «счёте» и «охоте» бот заходит картой с минимальным шансом и не подкидывает то, что защитник скорее всего покроет.
* **Память играет, но молчит.** Карты, которые бот запомнил, влияют только на ходы. Реплики про чужие карты («помнишь,
  ты мне это подкидывал», «та самая 7♠») убраны: они раздражали и иногда называли не ту карту. Бот говорит только о
  том, что видно всем.
* **Стол помнит людей** (`store.Profile`, `bot.Dossier`). По игроку в Redis лежит профиль без TTL: игры, проигрыши,
  взятые карты, рекорд взятия за раз, заходы по мастям, клеймо. Движок копит статистику партии на месте
  (`Player.Stats`), хаб сворачивает её в профиль, когда игра закончена (там же, где начисляется победа). Любимая масть —
  та, с которой игрок заходит хотя бы в половине случаев при шести и более заходах. Бот встречает в лобби по досье:
  «О, Вася. Прошлый раз ты взял одиннадцать карт, помнишь?» (при входе человека и при посадке бота), а в игре
  подкалывает привычкой: «Опять с червей, Вася? Предсказуемо». Модель получает досье в промпте.
* **Клеймо дурака.** Проигравший получает `scar` до первой победы: красная «Д» на стикере, видна всем за столом и в
  лобби; экран результата говорит об этом. Смывается только победой (первым выходом), ничья ничего не меняет.
* **Боты между собой.** Реплика бота (не ответ) с вероятностью 0.35 вызывает ответ другого бота через 1.5–3.5 с
  («{имя}, ты бы молчал. У тебя семь карт»); ответы не образуют цепочек. Последняя реплика другого бота попадает в
  промпт модели, чтобы та могла ответить сама. События ботов (взял, бито, перевёл) тоже становятся поводом для
  подколки, но только когда люди ничего заметного не делали.
* **Боты растут в пределах стола.** Бот, оставшийся дураком, в следующей игре на уровень сильнее (лёгкий → обычный →
  сложный) и объявляет это первым же ходом: «Проиграл — поумнел. Теперь играю всерьёз».
* **«Шутка от админа».** Раз за игру (не раньше второго кона) бот ломает четвёртую стену — у правил есть набор
  реплик про админа и backend, модели это разрешается в промпте ровно один раз; повтор в той же игре исключён.
* Настроения и «уже пошутил» живут в памяти инстанса, который обслуживает комнату; при нескольких инстансах они могут
  разойтись — на ход это не влияет, ход защищён версией состояния.

## Админ-панель и статистика

`ADMIN_IDS` — Telegram user id (узнать: @userinfobot) или `dev:<id>`. Таким пользователям в лобби показывается кнопка
«АДМИН-ПАНЕЛЬ». Она читает `GET /api/admin/overview` (доступ подтверждается той же подписью `initData`, что и вход в игру):
аптайм, счётчики (входы, ходы, ошибки правил, начатые и законченные партии, ходы ботов моделью/правилами), состояние LLM
(модели в игре, запросы/успехи/ошибки, пауза, последняя ошибка, какая модель ответила последней), все столы с игроками,
таблица игроков по XP, последние события (ошибки правил с кодом, игроком и столом; старт/финиш партий; ошибки модели) и
последние 200 строк лога сервера. `GET /api/admin/room?id=X` отдаёт полное, несанитизированное состояние стола.
Всё это живёт в памяти инстанса (`internal/monitor`), стек логов не нужен.

**Опыт.** После каждой законченной партии игрокам-людям начисляется XP: 1 за партию и ещё 1, если ты не Дурак (ничья —
все не Дураки). Запись идемпотентна (ключ «стол + версия состояния»), хранится в Redis (`durag:user:<id>`, рейтинг
`durag:xp`) или в памяти. XP виден всем (`players[].xp`) и открывает реакции с эффектами.

**Реакции с эффектами** (`SEND_EMOJI`, сервер проверяет порог по XP, иначе `LOCKED_EMOJI`):

| XP | Эмодзи | Эффект | Звук |
| --- | --- | --- | --- |
| 3 | 😭 | слёзы падают по всему экрану | два грустных «вау-вау» |
| 6 | 🖕 | экран трясётся | гудок-зуммер |
| 9 | 🏆 | конфетти и плашка «ПОБЕДА»; после выигранной партии сервер сам отправляет её от победителя с репликой | фанфара |
| 12 | 🤣 | тряска и «ХА-ХА-ХА» | стаккато «ха-ха» |
| 15 | 💣 | вспышка, искры, «БУМ!» и тряска | удар и глухой взрыв |

Звуки синтезируются Web Audio API прямо в браузере (файлов нет); мобильные браузеры включают звук только после первого
касания экрана, поэтому первое касание разблокирует аудио. В панели эмодзи закрытые реакции серые с порогом XP;
админам (`ADMIN_IDS`) открыто всё сразу.

## Архитектура

```
backend/
  cmd/server/main.go          — HTTP/WS сервер, graceful shutdown
  internal/game/              — ядро правил (чистый Go, без I/O)
    card.go, deck.go          — модель карты, генератор 55 карт, сид-детерминированный shuffle
    state.go                  — GameState/Player (модель ТЗ + расширения), хелперы
    validator.go              — RuleError-коды и проверки всех интентов, CanBeat()
    engine.go                 — Join/Disconnect/Leave/SetReady/Start, PlayCard/TransferTurn/TakeCards/Pass,
                                конец кона: добор, пеньки, выбывание, финал
    sanitize.go               — Sanitized(viewer) — вид состояния для конкретного игрока
  internal/store/             — интерфейс Store; memory.go (dev/tests), redis.go (lock + TTL + Pub/Sub)
  internal/ws/                — протокол, аутентификация, Client (read/write pump), Hub (комнаты, relay)
  internal/telegram/          — валидация initData (HMAC-SHA256)
  internal/config/            — .env и переменные окружения
frontend/
  src/state/GameContext.tsx   — React Context: WebSocket с реконнектом, интенты, ошибки
  src/telegram/               — telegram-web-app.js: initData, ready/expand, haptic
  src/components/             — Lobby, WaitingRoom, GameScreen, Hud, Toast, ResultOverlay, Sticker, Button
  src/pixi/                   — TableScene (стол), CardView (карта), shaders (GLSL), tween (стоп-моушн), layout, suits
  src/util/rules.ts           — зеркало правил для подсказок (авторитет всегда у сервера)
deploy/                       — Nginx-шаблон, Certbot bootstrap
```

**Поток данных.** Клиент → `JOIN_ROOM`/`PLAY_CARD`/… → `Hub` → `Store.Update(roomID)` под блокировкой комнаты →
`Engine` валидирует и мутирует `GameState` → состояние сохраняется в Redis и публикуется в канал `durag:events:<room>` →
каждый инстанс бэкенда получает его и шлёт **каждому** своему клиенту `STATE_UPDATE` с `Sanitized(playerID)`.
При ошибке клиент получает `ERROR` и сразу `STATE_UPDATE` с актуальным состоянием.

## Сетевой протокол (WebSocket)

Эндпоинт: `GET /ws` (upgrade). Формат: `{"type": "...", "payload": {...}}`.

### Клиент → сервер (intents)

| Тип | Payload | Описание |
| --- | --- | --- |
| `JOIN_ROOM` | `{"room_id":"AB12","tg_init_data":"...","create":true,"dev_user":{"id":"x","name":"Имя"}}` | Вход в комнату. `create` — создать, если нет. `dev_user` учитывается только при `ALLOW_DEV_AUTH=true` и пустом `tg_init_data`. |
| `PLAY_CARD` | `{"card_id":"S_7","target_card_id":"S_6"}` | Без `target_card_id` — атака/подкидывание; с ним — отбой карты `target_card_id`. |
| `TRANSFER_TURN` | `{"card_id":"H_7"}` | Перевод. |
| `TAKE_CARDS` | — | «Беру». |
| `RESOLVE_BOUT` | — | «Бито» — больше не подкидываю (псевдоним `PASS` принимается). |
| `TAKE_STUMP` | — | Взять свой пенёк в шаге «пеньки» после кона (иначе сервер возьмёт его сам через `STUMP_AUTO_DELAY`). |
| `ADD_BOT` | `{level?: "easy"\|"normal"\|"hard"}` | Лобби: посадить бота (имя выдаёт сервер, бот всегда «готов»; хотя бы одно место остаётся людям). |
| `REMOVE_BOT` | `{"player_id":"bot:…"}` | Лобби: убрать бота. |
| `READY` *(расширение)* | `{"ready":true}` | Готовность в лобби. В завершённой игре `ready:true` сбрасывает стол в лобби. |
| `LEAVE_ROOM` *(расширение)* | — | Покинуть комнату (во время игры — сдача). |
| `SEND_EMOJI` | `{"emoji":"🔥"}` | Эмодзи-реакция (белый список: 👍 👎 😂 😡 😎 🤔 🔥 💀 🤡 ❤️ 👏 🙏 👊 🚬; псевдоним `REACT`). Лимит — одна реакция в 1,2 с. |
| `PING` *(расширение)* | — | Ответ `PONG`. |

| Тип | Payload |
| --- | --- |
| `STATE_UPDATE` | санитизированный `GameState` (см. ниже) + `viewer_id` |
| `ERROR` | `{"message":"...","code":"CANNOT_BEAT","card_id":"H_7"}` — `card_id` указывает, какую карту вернуть в руку |

## Защита от читов: санитайзинг состояния

`GameState.Sanitized(viewerID)` делает глубокую копию и:

* заменяет `deck` на `deck_count`;
* скрывает `trump_card` и `trump_suit`, пока основная колода не пуста;
* **все** пеньки (включая собственный) заменяет на `stump_count`;
* чужие `hand` заменяет на `hand_count`.

Клиент никогда не получает карты колоды, пеньков и рук оппонентов (тест `TestSanitizedHidesPrivateInformation` проверяет,
что их ID отсутствуют в JSON). Полное состояние ходит только между инстансами бэкенда через Redis.

## Дизайн и рендер (Indie Punk & Glitch, v10)

* **Фон** — тёмная потёртая бумага `#161513` с двумя слоями грубого зерна (SVG `feTurbulence` в `body::before/::after`,
  `mix-blend-mode`), без верхнего заголовка: весь экран отдан столу.
* **Статусы** — кислотно-жёлтые `#e6ff00` плашки-«скотч» с рваным `clip-path` и лёгким наклоном (`.status`), под рукой —
  панель действий («БЕРУ» / «БИТО» / пульсирующая «ВЗЯТЬ ПЕНЁК»). Ярлыки ролей у аватаров: «БЬЁТСЯ / БЕРЁТ / ХОДИТ / ПЕНЁК…».
* **Карты** — `PIXI.Graphics`: ровный прямоугольник со скруглением 4px (рваные контуры убраны — мешали читать карту),
  бумага `#ece9e1`, чернила `#0d0d0d`, вместо красных мастей — токсичная маджента `#cf1fff`; тень — полупрозрачная
  бумажная «призрачная» копия без blur. Масти — SVG-контуры (`GraphicsPath`), индексы — web-шрифт Unbounded (OFL).
* **Без шейдеров.** Фильтры halftone / chromatic / hologram / glitch и переключатель FX удалены: на iPhone
  (WebKit, Telegram WebView) отфильтрованная Супер-карта рендерилась чёрным прямоугольником. Супер-карта теперь —
  статичная «фольга»: диагональный радужный градиент (`FillGradient`, обычная текстура) под штриховкой, без
  единого кастомного шейдера. При необходимости старые шейдеры можно восстановить из истории git (коммит до
  «Drop every shader pass»).
* **Козырь, которым бьёшь, чуть светится.** Козырная карта, положенная как отбой (и козырь, который защищающийся
  поднял, чтобы отбиться), получает мягкое кислотное свечение — три скруглённых кольца убывающей прозрачности с медленным
  «дыханием»; никаких шейдеров и blur. Остальные карты не трогаются.
* **Супер-карта** — когда ею бьют, побитая карта **распадается** на грубые пиксели и крестики (`disintegrate`): частицы
  разлетаются стоп-моушном и гаснут.
* **Пеньки** — минималистичные стопки рубашек у каждого места; в шаге «пеньки» своя стопка подсвечена и реагирует на тап
  (`TAKE_STUMP`), карты вылетают из стопки в руку.
* **Таймер хода** — штрихованное круговое кольцо вокруг аватара (`TimerRing.tsx`, SVG, 24 ступени), краснеет
  (точнее — становится токсичным) на последней четверти.
* **Козырь** — скрыт до тех пор, пока его кто-то не возьмёт: последняя карта колоды вылетает в центр стола, вскрывается
  и улетает в руку взявшего; после этого у колоды стоит кислотная плашка с мастью.
* **Физика** — стоп-моушн твинер (`tween.ts`): значения обновляются 12 раз в секунду, пружинящие easing'и
  (`outBack` для ходов, `outElastic` для возврата карты по `ERROR`).
* **Drag-and-drop и оптимистичные ходы** — карту тащат на стол (атака/подкидывание), на атакующую карту (отбой) или в
  пустую зону стола будучи защищающимся (перевод); тап — «умный ход». Карта уходит на стол сразу и **возвращается в руку
  только по `ERROR` от сервера** (страховочный тайм-аут 15 с на случай потери сообщения), иначе остаётся там, где её
  подтвердил `STATE_UPDATE`.
* **Устойчивость WebGL** — при `webglcontextlost` сцена уничтожается через `app.destroy(true)` (освобождение контекста и
  текстур) и пересоздаётся заново; при переподключении сокета ожидающие карты сбрасываются (`clearPending`).
* **Карта не может «пропасть».** Анимация вскрытия козыря (карта летит в центр и затем в руку взявшего) заканчивается
  идемпотентным `finish()` и страховочным таймером: своя карта в руке становится видимой в любом случае. Перетаскивание
  отменяется по `pointercancel` (системный жест iOS/Telegram), при сворачивании вкладки и если карты уже нет в руке —
  «зависшая» карта не блокирует ввод. Карта, разнесённая Супер-картой и вернувшаяся в руку (защищающийся взял стол),
  снова рисуется целой. `?debug=1` кладёт в `window.__durag` сцену с `debugSnapshot()` (видимость карт руки, pending,
  drag, состояние вскрытия) — этим пользуются сквозные тесты.

### Свет над столом

Одна лампа (`pixi/lamp.ts`), три движения, все — замкнутые формулы от времени, ничего не симулируется:

* **дрейф** — фигура Лиссажу `x = ½ + 0.35·cos(ωt)`, `y = 0.35 + 0.22·sin(1.3ωt)` с периодом 60 с: несоизмеримые частоты,
  картина не повторяется;
* **качание от кулака** — затухающий маятник `θ(t) = A·e^(−1.2t)·cos(2πt/1.1)` после 👊: тени пару секунд ходят ходуном;
* **взгляд** — лампа тянется к побитой карте (вес растёт за 150 мс до 0.6 и отпускает за полсекунды).

Свет живёт внутри canvas (DOM-слой с blend-mode поверх WebGL — ровно то, что мобильные браузеры рисуют с ошибками):
тёмный лист с мягкой дырой там, где висит лампа (одна радиальная текстура, спрайт шириной в три экрана, так что дыра
может уйти в угол, а дальний угол останется тёмным), рука игрока выше этого слоя — она «под своим носом» и не темнеет.
От лампы же считаются тени карт (направление от лампы к карте, длиннее вдали и у поднятой карты; шаг 12 к/с, как и
вся анимация) и центр CSS-виньетки (`--lx/--ly`, 10 раз в секунду). **Лампа мигает:** раз в 15–75 с (экспоненциальная
пауза, чтобы не читалось расписание) серия из 2–5 быстрых провалов яркости `1 − A·|sin(πku)|·(1 − u/2)` за 250–750 мс;
удар кулаком тоже выбивает контакт. **Супер-карта — второй источник света:** у неё постоянный ореол, аддитивное
свечение на столе, а тени соседних карт расходятся от неё с весом `e^(−d/R)`, так что рядом с ней свет её, через стол —
лампы.

**Взгляд.** Каждый отбой: стол на 320 мс наезжает на побившую карту (масштаб 1 → 1.1 вокруг точки карты: слой стола
сдвигается в `(1−s)·P`, карта стоит на месте; рука и колоды не двигаются), пауза, назад. Стикер игрока в это время
наклоняется в сторону карты (до 5°), лампа тоже смотрит туда.

**Подбросы — только локальные:** от Джокера (побив карту, делает полный оборот с лёгким раздуванием, соседние карты
подпрыгивают), от Супер-карты (взрыв разбрасывает карты вокруг) и от кулака. Та же волна `H·e^(−d/R)`, разный радиус.

**Глаз игрока** (`pixi/camera.ts`). На стол смотрит голова, а не штатив: мир (`world`) чуть ходит под камерой —
медленное дыхание из двух синусоид на ось с несоизмеримыми периодами 9–20 с (пара пикселей) и крен в 0.2°; раз в
25–65 с глаз «приглядывается» — наезд 1 → 1.03–1.045 вокруг случайной карты на столе (или центра стола), 0.9 с туда,
пауза, 0.9 с обратно. Моргания нет: читалось как сбой, а не как глаз. Начало перетаскивания отпускает наезд, координаты указателя переводятся в систему мира, так что карта остаётся под
пальцем. `prefers-reduced-motion` выключает камеру целиком.

**Лёгкие эффекты** (`util/fx.ts`). Режим в лобби: «авто / полные / лёгкие». Лёгкие выключают лампу, движущиеся тени,
камеру, два слоя процедурной бумажной фактуры (самое дорогое на странице) и размытие дыма; остаются сами карты, волны и
взгляд. «Авто» начинает с полных и судит телефон по кадрам: экспоненциальное среднее времени кадра (α = 0.05, ≈ 20
кадров) сравнивается с порогом 30 мс после 4 с разогрева (раздача тяжёлая нарочно), и только если среднее держится
выше порога 3 с подряд, вердикт «лёгкие» запоминается на устройстве, стол переключается на лету и тост говорит об
этом. Одиночный медленный кадр (GC, свёрнутая вкладка) ничего не переключает.

**Обряд пенька.** Взятие пенька — единственный момент, которого нет в обычном дураке, и у него свой ритуал: лампа
гаснет (250 мс), в темноте карты пенька переворачиваются лицом (быстрый поворот вокруг вертикальной оси, лицо
появляется на половине), и свет возвращается (450 мс). Щелчок выключателя в обе стороны. Темноту видят все за столом,
переворот в темноте — тот, кто брал. В лёгком режиме лампы нет, карты всё равно переворачиваются.

**Герой.** Стикер игрока держит руку: стоит слева от веера на уровне карт (веер отступает на `HAND_INSET`), дышит и
изредка косится в сторону (CSS-анимации). Рядом с рукой чип сортировки: по достоинству или по масти (спецкарты
всегда в конце), запоминается в `durag.sort`. Четыре и больше соперников встают в один компактный ряд без имён;
пузыри реплик у правых стикеров открываются влево и не обрезаются.

## Тесты

```bash
cd backend && go test -race ./...     # правила (TDD: validator_test.go, engine_test.go), сторы (miniredis), WS-хаб, Telegram
```

санитайзинг и реакцию `ERROR` + `STATE_UPDATE` на невалидный ход.

доигрывают партию до последней карты колоды, затем браузер садится на место атакующего и через реальный UI добирает
козырь (анимация вскрытия, карта обязана оказаться видимой в руке), разыгрывает руку до шага «пеньки» и берёт пенёк
(`TAKE_STUMP`, статусы, ярлыки, второй браузер — вид соперника); `frontend/e2e/bots.mjs` — браузер сажает бота из лобби,
играет с ним несколько конов и ловит его реплики (`REACTION` с `text`); `frontend/e2e/premium.mjs` — два WebSocket-бота
доигрывают партии, пока у игрока не наберётся 9 XP, затем браузер проверяет панель реакций с замками по XP, эффект 🏆
(конфетти, звук, `REACTION` с `effect` у соперника), отказ `LOCKED_EMOJI` и админ-панель (бэкенд с `ADMIN_IDS=dev:admin-e2e`);
`frontend/e2e/admin-ui.mjs` — узкий экран 360×600: чип админа и кнопки лобби на месте, из комнаты ожидания можно вернуться
в меню, админу с 0 XP доступна 💣 с эффектом.

Кратко:

```bash
git clone https://github.com/BreezeAreaSay/durag.git /opt/durag && cd /opt/durag
./deploy/server-setup.sh                   # Docker + compose plugin + ufw (один раз)
cp .env.example .env                       # TELEGRAM_BOT_TOKEN, DOMAIN, CERTBOT_EMAIL, VITE_BOT_USERNAME, VITE_APP_SHORTNAME
./deploy/init-letsencrypt.sh               # первый сертификат (STAGING=1 для тестового окружения LE)
./deploy/deploy.sh                         # сборка, запуск, health-check; это же — обновление
```

`docker-compose.prod.yml`: Nginx (TLS, HTTP→HTTPS, статика SPA, проксирование `/ws` с `Upgrade`, `/api`), Certbot
(автопродление каждые 12 ч, Nginx перечитывает сертификаты каждые 6 ч), бэкенд (`ALLOW_DEV_AUTH=false`,
`ALLOWED_ORIGINS=https://$DOMAIN`), Redis с AOF. Несколько реплик бэкенда: `--scale backend=N` — комнаты синхронизируются через Redis.
GitHub Actions: `ci.yml` (тесты, сборка, Docker-образы) и `deploy.yml` (выкат по SSH).
